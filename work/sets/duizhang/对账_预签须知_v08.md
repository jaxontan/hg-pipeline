## 一、预签前必须落到纸面的 5 项（M1–M5）

### M1 · 预签表签不到它声称要签的东西
§零 写「预签只签光位、能量、回路、机位清单」，但 §五 只剩「角色 / 姓名 / G0 已关闭 ☐ / 日期」——
可勾的是闸门状态，不是那四张清单；v06 的「意见/条件」列在重排时丢了。条件签没有记录条件与保留意见的地方，等于签了个空。

**批注**：§五 恢复「意见 / 条件」列，保留「G0 已关闭 ☐」。另 §一 抬头写「摄影指导签」、§二/§五/§六 写「四方」，§一 到底谁签须统一。

### M2 · 预填数值缺「条件性·无效」标记
§一 的 0.40 m 净空、§二 的 imax 0.11 / LEAK 0 全部由 24×12×3.5 占位尺寸算出，
但「G0 关闭前一律标条件性·无效」只在 §三 出现一次。签字人翻到满表具体数字，容易当成已验实测值。

**批注**：§一、§二 抬头各加一行「以下数值基于占位尺寸，G0 关闭前一律为条件性·无效」。

### M3 · ① = 否 的三个分支都会改 .blend
撤灯 → B03 灯数 11+10 变 11+9，manifest L3 与 §一 光位表全变；移场 / S37 改到有电空间同样动灯与机位。
现文字里「须重建 + 重 VERIFY」只挂在第三个分支，前两个可能被当作「纸面改改就行」。

**批注**：改为「三者均须回构建器重建 + 重 VERIFY + 新 sha256」。

### M4 · NORMAL 态的 LEAK 0 有 7/8 机位是空验
NORMAL 态除 `CAM_S00_overview` 看到 11 盏外，其余 7 台 `LIGHTVIS 0 in frame`（顶灯 z=3.10 在视锥上方），
LEAK=0 是「根本没有灯入画」的必然结果，不构成同等强度的验证；真正有检验力的是 BLACKOUT 态。

**批注**：§二 核对列补 `LIGHTVIS n`，或表脚注明「NORMAL 态 LEAK 0 多为无灯入画，验证强度以 BLACKOUT 态为准」。
（不影响「两态均已实测」的事实，只影响签字人能读出多少。）

### M5 · build.log 抬头陈旧
第 52 行仍写 `B04 CAMERAS 8 (visibility measured in state=BLACKOUT)`，其下却已是 `state=NORMAL` 与 `state=BLACKOUT` 两块。
核验文档里自相矛盾的状态声明，比 md 里的更该改。

**批注**：改为 `visibility measured in state=NORMAL + BLACKOUT`，或删掉该行。
