# AIGC-PP2 — a local AI 漫剧 production pipeline

A self-hosted, fully local pipeline for producing a 30-episode short-form drama series
(60–90 minutes total) for YouTube / TikTok / 红果. No cloud inference, no per-clip billing,
no upload of footage or reference art.

Everything runs on one machine: an NVIDIA DGX Spark (GB10) at `tdadmin@192.168.1.103`,
inside `~/Desktop/AIGC-PP2`. Deleting that one directory removes the entire project.

**Style: photoreal cinematic.** Chosen after a head-to-head comparison of three engines on the
same shot (see [§7](#7-measured-performance)).

---

## 1. What we are doing

| | |
|---|---|
| **Deliverable** | 30 episodes × 2–3 min, vertical 1080×1920, Chinese dialogue, 24 fps |
| **Genre form** | 漫剧 — a comic-drama shot list: short shots, strong beats, dialogue-driven |
| **Look** | Photoreal cinematic, low-saturation film grade, shallow DOF, 35 mm grain |
| **Distribution** | YouTube Shorts, TikTok (Douyin), 红果短剧 |
| **Licensing stance** | Only models whose licence we read ourselves and that are clean for commercial worldwide use |

The production loop is deliberately simple and reproducible:

```
story → character sheet → keyframe → video shot → voice line → lip-sync insert → assemble → episode
         FLUX.2-Klein     Z-Image    LTX-2.5     Qwen3-TTS   Wan S2V          ffmpeg
```

**Since 2026-11-17 the production loop is keyframe-first** — every shot starts from a still that
is conditioned on the character sheet and the location plate, so the cast stays the same person
from shot to shot, and dialogue is lip-synced at full resolution by the same model as every
other shot:

```
bible + shot list → character sheets → keyframes → voice → animatic → video → assemble
                    Klein (+refs)      Klein+refs  Qwen3   ffmpeg     LTX-2.5   ffmpeg
                                                                      i2v / talk
```

One command drives it: `pipeline.cli produce --show <show> --episode <ep> --stage all`.
The full method — roles, shot-list schema, camera vocabulary, review gates — is in
**[workflows/PRODUCTION_WORKFLOW.md](workflows/PRODUCTION_WORKFLOW.md)**. The text-only loop
above still works and is what §5.1–5.9 document.

There is no timeline editor in the loop. Each shot is a prompt plus parameters, generated by a CLI
command, normalised and concatenated by `pipeline/assemble.py`. That is what makes 30 episodes
tractable: a shot is a line of text you can regenerate, not a manual edit you have to redo.

| Dialogue / lip-sync | Wan 2.2 S2V 14B fp8 + 4-step LoRA | 16.4 GB | Apache-2.0 | ✅ unrestricted |
| Motion transfer | Wan 2.2 Animate 14B int8 + relight LoRA | 18.4 GB | Apache-2.0 | ✅ unrestricted |
| Keyframes | Z-Image-Turbo nvfp4 | 4.5 GB | Apache-2.0 | ✅ unrestricted |
| Character sheets | FLUX.2-Klein-4B | 7.8 GB | Apache-2.0 | ✅ unrestricted |

Supporting weights (text encoders, VAEs, audio encoder, upscaler) are listed in
[§5](#5-the-seven-workflows). Total: 115 GB.

### Models we deliberately did not use

| Model | Why not |
|---|---|
| **MiniMax H3** | Licence excludes EU / UK / South Korea / **USA** — unusable for YouTube or TikTok. Also requires a "MiniMax H3" credit in the UI, and a paid licence above $20 M/yr. Would be legal for China-only (红果) distribution, but that splits the release strategy. |
| **All Tencent Hunyuan video/image models** | Licence "does not apply in the European Union, United Kingdom and South Korea" — the same trap. Avoided as a family. |
| **Qwen-Image 2.1** | Qwen *Research* Licence = research/evaluation only. Not commercial. |
| **FLUX.3 Klein** | Gated repo; licence unreadable without accepting terms. Used **FLUX.2-Klein** (Apache-2.0) instead. |

### The one licence worth reading twice

**LTX-2 Community Licence** — Apache-2.0-like, no geography restriction, but it converts to a paid
commercial licence at **$10 M annual revenue**. Below that, it is free for commercial use including
monetised YouTube/TikTok. Re-read it before any distribution deal.

## 5. The seven workflows

Each "lane" is a fixed, tested node graph. Parameters live in `pipeline/config.json`; the graph
itself is built by `pipeline/graphs.py`. `workflows/<lane>.api.json` is an exported snapshot you can
drag into the ComfyUI UI to look at it.

```bash
venv/bin/python -m pipeline.cli describe --lane video_ltx_final   # read it as text
venv/bin/python -m pipeline.cli lanes                             # all lanes + measured cost
```

---

### 5.1 `image_fast` — keyframes (Z-Image-Turbo)

**What it does:** turns a description into one still. This is the workhorse for establishing shots,
backgrounds, props, and the reference frame that a dialogue shot stands on.

**Graph (11 nodes):** `UNETLoader → ModelSamplingAuraFlow(shift 3.0) → KSampler`
with `CLIPLoader(lumina2) → CLIPTextEncode` ×2 and `EmptySD3LatentImage`; `VAEDecode → SaveImage`.

| Setting | Value |
|---|---|
| Resolution | 832 × 1216 (vertical) |
| Steps / CFG | 8 / 1.0 |
| Sampler | `res_multistep` / `simple` |
| Speed | **9.0 s** |
| Command | `pipeline.cli image --lane image_fast --prompt "…" --out man_01` |

Text-to-image only — no reference image, so character consistency has to come from the prompt and
from reusing a seed.

---

### 5.2 `image_character` — character sheets (FLUX.2-Klein-4B)

**What it does:** designs a character: face, build, wardrobe, era styling. Klein's prompt adherence is
noticeably better than Z-Image for *specific* descriptions, which is what a recurring cast needs.

**Graph (14 nodes):** `UNETLoader → CFGGuider(cfg 1.0)` + `Flux2Scheduler → SamplerCustomAdvanced`
with `EmptyFlux2LatentImage`; `VAEDecode → SaveImage`. Note the different sampler path — FLUX.2 uses
a flow scheduler, not a plain KSampler.

| Setting | Value |
|---|---|
| Resolution | 896 × 1152 |
| Steps / CFG | 4 / 1.0 |
| Sampler | `euler` + `Flux2Scheduler` |
| Speed | **6.0 s** |
| Command | `pipeline.cli image --lane image_character --prompt "…" --out chen_sheet` |

**Consistency** was the open problem for a 30-episode series when this lane was text-only. It is
now handled by the `image_ref` lane (§5.10): the same Klein model, with the character sheet and
location plate chained in as reference latents. A per-character LoRA remains the next step up if
a lead needs to hold through extreme angles.

---

### 5.3 `video_ltx_preview` — animatic (LTX-2.5 single pass)

**What it does:** the cheap "is the cut working?" pass. Full motion, native audio, 512×768, at
roughly **one third** the cost of a final shot. Block a whole episode, judge pacing, throw it away.

**Graph (20 nodes):** `LTXVConcatAVLatent(video + audio latent) → LTXVDualCFGGuider →
SamplerCustomAdvanced (8 manual sigmas) → LTXVSeparateAVLatent → VAEDecodeTiled + LTXVAudioVAEDecode
→ CreateVideo`.

| Setting | Value |
|---|---|
| Resolution | 512 × 768 |
| Length | 97 frames @ 24 fps = 4.04 s |
| Sigmas | `1.0, 0.99375, 0.9875, 0.98125, 0.975, 0.909375, 0.725, 0.421875, 0.0` |
| Sampler / CFG | `euler_ancestral`, dual-CFG video 1.0 / audio 1.0 |
| Speed | **50.1 s** (~12× realtime) |
| Command | `pipeline.cli video --lane video_ltx_preview --prompt "…" --out anim_001` |

---

### 5.4 `video_ltx_final` — production shots (LTX-2.5 two-pass)

**What it does:** the real shot. Generates a draft at 512×768, upscales the *latent* 2× with a
purpose-trained upscaler, then refines with a short second sampling pass. Audio is carried through
both passes, so every clip arrives with sound.

This is the lane the whole show runs on: it is both **faster in wall-clock** and **sharper** than
the Wan alternative.

**Graph (29 nodes), in order:**

```
UNETLoader ─┐
CLIP ─> CLIPTextEncode ×2 ─> LTXVConditioning ─┐
                                               ├─> LTXVDualCFGGuider
EmptyLTXVLatentVideo ─┐                        │
LTXVEmptyLatentAudio ─┴─> LTXVConcatAVLatent ─> pass 1 (8 sigmas)
                                                     │
                            LTXVLatentUpsampler ×2 <──┤
                                                     ▼
                                          pass 2 (4 sigmas from 0.85)
                                                     │
                        VAEDecodeTiled ──┬───────────┘
                        LTXVAudioVAEDecode ┴─> CreateVideo ─> SaveVideo
```

| Setting | Value |
|---|---|
| Draft → final | 512×768 → **1024×1536** |
| Length | 97 frames @ 24 fps = 4.04 s |
| Pass 2 sigmas | `0.85, 0.7250, 0.4219, 0.0` |
| Speed | **125 s** cold (31× realtime), 180 s after a model swap |
| Command | `pipeline.cli video --lane video_ltx_final --project ep01 --prompt "…" --out shot_001` |

Prompting note: this lane generates its own ambience. Keep the prompt about picture only; dialogue
belongs in the S2V lane.

---

### 5.5 `video_wan_t2v` — draft / image-to-video fallback (Wan 2.2 TI2V 5B)

**What it does:** an alternative motion model. Slower and softer than LTX, but it keeps a different
strength: `Wan22ImageToVideoLatent` accepts a first-frame image, so it can lock a specific still and
animate from it.

**Graph (11 nodes):** `UNETLoader → ModelSamplingSD3(shift 8) → KSampler(20 steps, cfg 5, uni_pc)`
with `Wan22ImageToVideoLatent`; `VAEDecode → CreateVideo → SaveVideo`.

| Setting | Value |
|---|---|
| Resolution | 704 × 1280 |
| Length / steps | 121 frames @ 24 fps / 20 steps, CFG 5 |
| Speed | **324.6 s** (13.5 s/it), 455 s under contention — 90× realtime |
| Command | `pipeline.cli video --lane video_wan_t2v --prompt "…" --out draft_001` |

Three times slower than LTX for a softer frame. Use it when you need I2V, not as a default.

---

### 5.6 `video_s2v` — dialogue / lip-sync (Wan 2.2 S2V 14B)

**What it does:** takes a still **and a voice wav**, and produces the actor saying that line with
matched lip movement, head motion and blinks. This is how characters speak.

**Graph (16 nodes):**
`LoadAudio → AudioEncoderEncode(wav2vec2)` → `WanSoundImageToVideo`, which also consumes the
reference still; `UNETLoader → LoraLoaderModelOnly(4-step LoRA) → ModelSamplingSD3(shift 8)` →
`KSampler(4 steps, cfg 1)` (`positive`/`negative`/`latent` all come from the S2V node) →
`VAEDecode → CreateVideo(images, audio)`.

| Setting | Value |
|---|---|
| Resolution | 480 × 832 |
| Length | **derived from the wav**: `((round(dur×16)+1−1)//4)·4+1` frames, so audio never drifts |
| Steps / CFG | 4 / 1.0 (4-step lightx2v LoRA) |
| Speed | **130 s** warm, 224 s cold |
| Command | `pipeline.cli dialogue --prompt "…" --audio assets/audio/line_01.wav --ref ref_001.png --out shot_002` |

**Two hard-won rules:**

1. **The reference must be a scene frame, not a character sheet.** Given a white-background sheet it
   faithfully reproduced a white background and a near-static pose. Given an LTX frame it produces a
   proper dialogue shot in that location — which is why the production order is *video first, then
   extract a frame, then lip-sync*.
2. **480×832 is soft.** Assembly upscales it to 1080×1920, so dialogue shots are visibly less sharp
   than LTX shots. If dialogue dominates screen time, an upscale/refine pass on S2V output is the
   next thing to add.

---

### 5.7 `video_animate` — motion transfer (Wan 2.2 Animate 14B)

**What it does:** copies body motion from a **driving video** onto a character still, preserving the
character's identity. Intended for action beats that are hard to prompt.

**Graph (17 nodes):** `LoadVideo → GetVideoComponents` (pose) + `CLIPVisionEncode` (identity) →
`WanAnimateToVideo` → `KSampler(10 steps, cfg 5)` → `TrimVideoLatent` → `VAEDecode → CreateVideo`.

| Setting | Value |
|---|---|
| Resolution | 480 × 832, 49 frames @ 16 fps |
| Steps / CFG | 10 / 5.0, shift 5.0 |
| Speed | **275–376 s** — 123× realtime, the most expensive lane |
| Command | `pipeline.cli animate --prompt "…" --ref a.png --drive b.mp4 --out act_01` |

**Currently not usable for production.** Fed our own AI-generated clip as the driving video, the
output smeared: an AI clip's geometry wobbles frame to frame, so the pose signal contradicts itself.
It needs real camera footage (a phone clip is enough) before it earns a slot. Last resort anyway —
it costs 5× S2V for half the frames.

---

### 5.8 Voice — `voice` (Qwen3-TTS 1.7B VoiceDesign)

**What it does:** generates a Chinese voice line from text plus a vocal description. Not a ComfyUI
node — ComfyUI's only TTS nodes are paid cloud APIs (ElevenLabs, FishAudio, HeyGen, Breeze), so the
voice lane is a CLI step that writes wavs into `assets/audio/`, which `LoadAudio` then picks up.

| Setting | Value |
|---|---|
| Sample rate | 24 kHz mono wav |
| Model load | 27 s, then **5.7 s** per 6 s line |
| Voice control | a Chinese description, e.g. `中年男性，沙哑低沉的嗓音，说话缓慢，带一点北方口音，情绪克制而疲惫` |
| Command | `pipeline.cli voice --text "老陈，这搪瓷缸子跟了你二十年了。" --out line_01` |

Voice consistency across episodes works the same way character consistency does: keep the
`--instruct` string fixed per character. Voice *cloning* from a reference wav is supported by the
model but deliberately not used — it would require a licensed voice donor.

---

### 5.9 Assembly — `assemble`

Not a model; the step that makes it an episode. Every clip is normalised to **1080×1920, 24 fps,
H.264 + AAC 48 kHz**, letterboxed rather than cropped, then concatenated in the order given by
`shots.json`.

```bash
venv/bin/python -m pipeline.cli assemble --shots projects/ep01/shots.json --out projects/ep01/ep01.mp4
```

This is what lets a 1024×1536 LTX shot, a 480×832 S2V insert and a 704×1280 Wan shot sit in one
timeline without a single manual edit.

---

### 5.10 Reference-conditioned lanes (added 2026-11-17)

Three lanes that take images as well as text. They are what `produce` runs; details and the
reasoning are in [workflows/PRODUCTION_WORKFLOW.md](workflows/PRODUCTION_WORKFLOW.md).

| Lane | Engine | In → out | Measured |
|---|---|---|---|
| `image_ref` | FLUX.2-Klein-4B + `ReferenceLatent` ×N | sheet + plate + prompt → 1088×1920 keyframe | 18–21 s |
| `video_ltx_i2v` | LTX-2.5 two-pass, keyframe pinned by `LTXVImgToVideoInplace` (0.7 draft, 1.0 refine) | keyframe + prompt → 1088×1920 shot with ambience | 241–246 s per 4 s shot (~60× realtime) |
| `video_ltx_talk` | same, plus the voice wav through `LTXVAudioVAEEncode` with a zero noise mask | keyframe + wav + prompt → lip-synced 1088×1920 shot | 240 s per 4 s line |

```bash
venv/bin/python -m pipeline.cli image --ref sheet.png --ref plate.png --prompt "…" --out key_01
venv/bin/python -m pipeline.cli video --lane video_ltx_i2v --image key_01.png --prompt "…" --out s01
venv/bin/python -m pipeline.cli talk  --image key_01.png --audio line_01.wav --prompt "…" --out s02
```

These lanes are native 9:16 (544×960 draft → 1088×1920), so assembly crops 8 px instead of
letterboxing or upscaling. `video_ltx_talk` is the default for dialogue: same model and
resolution as the surrounding shots, and no frame-extraction step. `video_s2v` stays as the
per-shot fallback, because LTX sometimes paints captions into a dialogue shot.

Two things learned while measuring them:

- **At CFG 1.0 the negative prompt does nothing.** Modern cars drifted into a 1983 street with
  and without "no cars" in the prompt. Control the era at the keyframe, and keep `motion` small
  enough that the camera does not reveal background the keyframe never showed.
- **`LTXVEmptyLatentAudio` in the two text-only LTX lanes is built at 25 fps against 24 fps
  video**, so their ambience track is 3.88 s on a 4.04 s clip. Harmless after assembly; the new
  lanes pass the real frame rate.

## 6. Driving it

```bash
ssh tdadmin@192.168.1.103
cd ~/Desktop/AIGC-PP2 && . ./env.sh

venv/bin/python -m pipeline.cli health            # is ComfyUI up?
venv/bin/python -m pipeline.cli lanes             # every lane + measured cost
venv/bin/python -m pipeline.cli describe          # every graph as readable text
```

A complete shot, start to finish:

```bash
# 1. character sheet
venv/bin/python -m pipeline.cli image --lane image_character --project ep01 \
  --prompt "中年中国男人，藏蓝中山装，短发微白，1980年代县城气质" --out chen_sheet

# 2. the shot itself
venv/bin/python -m pipeline.cli video --lane video_ltx_final --project ep01 \
  --prompt "Photoreal cinematic: 1970s county-town street at dusk, …" --out shot_001

# 3. pull a frame out to use as the dialogue reference
ffmpeg -y -ss 2 -i outputs/ep01/video_ltx_final/shot_001_00001_.mp4 -frames:v 1 assets/input/ref_001.png

# 4. the line
venv/bin/python -m pipeline.cli voice --project ep01 --out line_01 \
  --text "老陈，这搪瓷缸子跟了你二十年了，扔了怪可惜的。" \
  --instruct "中年男性，沙哑低沉的嗓音，说话缓慢，带一点北方口音，情绪克制而疲惫"

# 5. lip-sync it
venv/bin/python -m pipeline.cli dialogue --project ep01 --out shot_002 \
  --prompt "A middle-aged man in a navy Mao suit speaks to camera on a small-town street at dusk" \
  --audio assets/audio/line_01.wav --ref assets/input/ref_001.png

# 6. cut them together
venv/bin/python -m pipeline.cli assemble --shots projects/ep01/shots.json --out projects/ep01/ep01.mp4
```

Every run appends one line to `projects/<name>/manifest.jsonl` with the lane, the prompt, every
parameter, a `graph_hash` (SHA-256 of the exact submitted graph) and the elapsed time. Any take can
be reproduced or diffed against a later change.

## 7. Measured performance

All numbers below were measured on this machine, not estimated.

### Same shot, three engines (photoreal cinematic)

| Engine | Resolution | Time | × realtime | Result |
|---|---|---|---|---|
| **LTX-2.5 two-pass** | **1024×1536** | **125 s** | 31× | Era-correct signage, real car and cyclist, believable skin, cinematic DOF — **chosen** |
| Wan 2.2 TI2V 5B | 704×1280 | 455 s | 90× | Right props and mood, but dark and soft |
| Wan 2.2 Animate 14B | 480×832 | 376 s | 123× | Smeared (bad driving clip) |

LTX wins on both axes — it is *faster in wall-clock per finished second* and renders 4× the pixels.

### Cost per lane

| Lane | Resolution | Clip length | Time | × realtime |
|---|---|---|---|---|
| `image_fast` | 832×1216 | still | 9 s | — |
| `image_character` | 896×1152 | still | 6 s | — |
| `video_ltx_preview` | 512×768 | 4.0 s | 50 s | 12× |
| `video_ltx_final` | 1024×1536 | 4.0 s | 125 s | 31× |
| `video_wan_t2v` | 704×1280 | 5.0 s | 325–455 s | 90× |
| `video_s2v` | 480×832 | audio-length | 130–224 s | 22× |
| `video_animate` | 480×832 | 3.1 s | 276–376 s | 123× |
| `voice` | 24 kHz | 6 s line | 5.7 s | ~1× |

### Season budget

90 minutes of finished video at 31× realtime is **~46 h of pure GPU time** for the video lanes in a
single pass with no retries. With an animatic pass and a realistic 2.5× retry overhead, budget
**~5–7 days of machine time** for the season — about **3–4 h per 3-minute episode** once the workflow
is stable, which fits an overnight batch of 3–4 episodes.

> **The keyframe-first lanes (§5.10) cost about twice this**: ~60× realtime at 1088×1920, so one
> take of a 2.5-minute episode is ~2.5 h of video rendering and a 75-minute season ~76 h. See
> `workflows/PRODUCTION_WORKFLOW.md` §5 for the measured table.

Timings drift with model swapping (LTX 125 s cold vs 180 s after another model has occupied memory).
Batch by lane, not by episode.

## 8. Known limits

| Limit | Impact | Fix |

## 9. Operations

### Access

The UI is at **http://192.168.1.103:9090** (bound `0.0.0.0`). Drag any
`workflows/*.api.json` onto the canvas to see a lane's graph.

> **Security:** ComfyUI has no authentication, and custom nodes execute arbitrary Python. While bound
> to `0.0.0.0`, anyone who can reach that port can run code as `tdadmin`. Fine on a trusted home LAN;
> flip it back otherwise.
>
> ```bash
> pkill -f 'ComfyUI/main.py'
> COMFY_BIND=127.0.0.1 bash ~/Desktop/AIGC-PP2/start_comfy.sh
> # remote alternative: ssh -N -L 9090:127.0.0.1:9090 tdadmin@192.168.1.103
> ```

### Restart / health

```bash
pkill -f 'ComfyUI/main.py'; nohup bash ~/Desktop/AIGC-PP2/start_comfy.sh > /dev/null 2>&1 &
venv/bin/python -m pipeline.cli health
tail -f ~/Desktop/AIGC-PP2/logs/comfyui.log
```

### Rules this project follows

1. Everything lives inside `$ROOT`. Caches, temp files and weights included.
2. **Do not touch the Oracle services or containers** (`ords-26ai`, `oracle-free-26ai`).
3. `ornith-vllm` is only ever `docker stop`ped — never removed. Restart with `docker start ornith-vllm`.
   It holds ~42 GiB of unified memory; stopping it raised free RAM from 52 → 98 GiB.
4. No `sudo`, no `apt`, no system or firewall changes without asking.
5. No Docker for this project — images would land outside `$ROOT`.
6. Never handle passwords or tokens. Gated repos are the human's job to accept.
7. On failure: stop and report the exact error.

### Uninstall

```bash
pkill -f 'ComfyUI/main.py'
rm -rf ~/Desktop/AIGC-PP2
docker start ornith-vllm
```
